# UI, motion and effects design system

Status: proposal. This document and `docs/design-tokens.json` are where colour, typography, shape, duration, easing and effect-budget values are born. Every value is an initial proposal; the owner approves values by merging the pull request that adds or changes them. A later change edits the JSON and the generated tables in the same PR.

`docs/design-tokens.json` is the single source of the values. This file explains how they are used. `node tools/design-tokens/design-tokens.mjs` checks the tokens (contrast, frame-budget sums, monotonic score steps) and that the contrast table below matches them; CI runs it through `npm run test:tools`. The client reads the values from `client/Assets/HypeDomino/UI/Tokens/DesignTokens.cs`, generated by `npm run tokens:gen` (`--csharp`); the same test fails when that file differs from the JSON, and the client never writes a colour by hand.

Frame, draw call, GC and tier definitions come from `docs/performance.md` and are not changed here. Client engine and asset delivery: `docs/adr/0001-client-unity.md`, `docs/adr/0002-asset-delivery.md`. Score events come from `docs/rules.md`; the client never computes a score, it presents the values the server sends.

## 1. Units

| Quantity | Unit |
|---|---|
| Length (type, radius, spacing, shake) | UI units on a canvas scaled to a 1080-unit short side (Canvas Scaler, scale with screen size, match the short side). Independent of orientation |
| Duration | ms |
| Easing | cubic-bezier `x1, y1, x2, y2` |
| Effect cost | ms of frame work time (`docs/performance.md` section 2) on the reference device of the level's tier |

On a 6.5-inch 20:9 phone the short side is about 2.67 in, so 1 in is about 405 units and 48 dp is about 120 units.

Rules:
- No text under 30 units (`typography.minimumSize`).
- Each family ships as a static SDF atlas holding the sets above plus every glyph in the localisation tables. No dynamic atlas in the match scene: adding a glyph at runtime allocates and stalls a frame.
- At most three material presets per family (plain, outline, glow); each preset costs a draw call.
- No runtime case conversion. Turkish and Azerbaijani map i to İ and ı to I, which culture-invariant upper-casing breaks; strings arrive from localisation already in their final case.
- Text size never animates. A text pop scales its transform.

## 4. Shape, space, elevation and glow

| Group | Tokens |
|---|---|
| `radius` | sm 8, md 16, lg 24, xl 36, pill 999 |
| `spacing` | xxs 4, xs 8, sm 12, md 16, lg 24, xl 32, xxl 48, xxxl 64 |
| `size.touchTargetMin` | 120 (about 48 dp) |
| `size.seatPanelWidth`, `size.seatPanelHeight` | 264, 216: one seat panel of the match screen (Match layout) |
| `size.handHeight` | 224: the hand strip of the match screen (Match layout) |
| `elevation` | e0 none; e1 offset 4, alpha 0.35; e2 offset 8, alpha 0.45; e3 offset 16, alpha 0.55 |
| `glow` | none; soft alpha 0.35, scale 1.15; strong alpha 0.55, scale 1.3; intense alpha 0.8, scale 1.5 |

- Shadows are a baked 9-slice sprite in `color.shadow`, offset down by the elevation's offset. No runtime blur.
- Glow is an additive sprite from the same atlas, tinted with a role `fill`, scaled from its owner by the glow's scale. It counts as one overdraw layer.
- No full-screen post-processing (bloom, blur, colour grading passes) in the match scene at any effect level.

## 5. Buttons and panels

| Element | Rest | Pressed | Released | Disabled |
|---|---|---|---|---|
| Button | Role `fill`, label in `label` style and role `on`, radius md (primary: pill), elevation e1, height at least `touchTargetMin`. Only the screen's primary button has `glow.soft` | Scale to `motion.pressScale` 0.94 in `micro` with `standard`; vertex tint `opacity.pressedTint` | Scale back to 1 in `fast` with `overshoot`. The action fires on pointer up inside, at once, not after the animation | `opacity.disabled`, no glow, no press motion |
| Panel | `surface.default`, radius lg, elevation e2, padding lg | - | - | - |

| Panel motion | Animation |
|---|---|
| Enter | Scale `motion.panelEnterScale` 0.92 to 1 and opacity 0 to 1, `moderate`, `enter` |
| Exit | Opacity 1 to 0 and scale 1 to 0.92, `base`, `exit` |
| Modal | Scrim fades to `opacity.scrim` in `base` alongside the panel |

- One primary button per screen. Destructive actions use `danger` and an icon.
- Close and back work during enter and exit animations; an exit interrupted by a new enter reverses from its current value.
- Clipping uses rectangle masks only; stencil masks break batching.

### Screens

Screens sit on a stack. The top screen takes input; back (the Android back key, Escape in the editor) pops it, and does nothing on the root screen. A modal is a screen drawn over the one below it with the scrim; the screen below stays visible and the scrim takes its taps.

| Screen motion | Animation |
|---|---|
| Push | The new screen: scale `motion.panelEnterScale` 0.92 to 1 and opacity 0 to 1, `slow`, `enter`. The screen below stays as it is under it and is hidden when the enter ends |
| Pop | The top screen: opacity 1 to 0 and scale 1 to 0.92, `base`, `exit`. The screen below shows at once under it |
| Modal open, close | Panel enter and exit above, with the scrim fading to `opacity.scrim` and back in `base` |
| Reduce motion | Opacity only, no scale; durations unchanged |
| Interrupted | Runs from its current value to the new end, for the duration scaled by the distance left, so a pop during a push reverses it |

- Input follows the stack, never the animation (section 6 rule 4): a pushed screen takes taps from its first frame and a popped one stops at once.
- Each screen is its own `Canvas`, screen space overlay, sorted by stack depth, so a change on one screen re-batches only that screen. Animated parts inside a screen sit on their own sub-canvas (section 6 rule 2).
- A hidden screen keeps its GameObject active and only its `Canvas` component is disabled. Its mesh stays built, so showing it again costs no rebuild.
- Every screen canvas scales its 1080-unit short side to the display's short side (section 1), and its content sits inside the safe area; the background may run under the insets.
- This holds from 16:9 to 21:9 phones, on 4:3 tablets and on nearly square folding displays, in either orientation. `AspectRatioTests` checks it on each device of the matrix (`docs/performance.md` 1) and on those shapes.

### Lists

A list that can hold more rows than fit on screen (shop, inventory, friends, leaderboard, history) recycles its rows.

- It keeps only the rows that cover the viewport, one more above and one more below, all created when the screen builds. Scrolling moves and rebinds them; it never instantiates or destroys a row and allocates 0 B.
- All rows of one list have the same height and gap, both tokens (`size.*`, `space.*`) the screen passes in. A list of mixed row heights is a design change.
- The scrolling content is its own sub-canvas without a layout group or content size fitter. Rows are placed directly, so scrolling re-batches only the list and never rebuilds layout (section 6 rule 2).
- A row is rebound only when it starts to show another item, or when its item changed. Rows past the last item are hidden.

### Match layout

The match screen places its regions inside the safe area with the same rules in either orientation, from 16:9 to 21:9 phones, on 4:3 tablets and on nearly square displays. `UI/Match/MatchLayout` computes them; nothing here depends on art.

| Region | Size | Place |
|---|---|---|
| Edge margin | `spacing.md` | Between the safe area edge and every region, and between neighbouring regions |
| Seat panel | `size.seatPanelWidth` x `size.seatPanelHeight` | Bottom: the local player, at the bottom left corner. Top: centred on the top edge. Left and right: on their edge, centred in the height above the bottom band |
| Hand | Height `size.handHeight` | Along the bottom edge, from the bottom seat panel to the right edge |
| Bottom band | The taller of the hand and a seat panel | The hand and the bottom seat panel share it |
| Board | What is left | Above the bottom band and under the top seat panel; in 2v2 between the left and right seat panels, in 1v1 across the full width |

- The local player always sits at the bottom. The other seats follow the turn order of R-7: turns pass clockwise, so in 2v2 the next seat is on the left, the partner (R-6) at the top and the last seat on the right. In 1v1 the opponent sits at the top and the sides stay empty.
- The seat order is North, East, South, West in 2v2 and X, Y in 1v1 (`docs/rules.md` Examples). A viewer without a seat is placed as South or X.
- Only the board gives way when room is short; on every shape above the regions stay inside the safe area and never overlap. On a safe area too small for the fixed regions the board shrinks to nothing.
- A seat panel holds the avatar with its frame, the name, the tile count and the turn timer. Their places inside the panel come with the panel art.

### Hand

The hand offers only what the server allows. The client never works out a legal move; it reads `legal_moves`, the opening fields and `turn_placements` of the latest `MatchView` (`proto/README.md`). `Game/Match/HandChoice` holds the rules below.

- **Selectable tiles.** While playing, a tile is selectable on the local player's turn when `legal_moves` names it. During the opening phase (R-9 to R-13) a forced opening makes only that tile selectable, and only for that seat; otherwise every tile is selectable for both players of the opening team. Other tiles stay in the hand without the highlight.
- **Tap.** A tap on a selectable tile with one legal end places it at once. With several legal ends (left and right, or a spinner arm, R-18) the tile is selected and its ends are highlighted on the board; a tap on one of them places it. A second tap on the selected tile, or a tap on another tile, changes the selection. An opening placement has no end (`BOARD_END_UNSPECIFIED`).
- **Drag.** Dragging a selectable tile and releasing it within `size.touchTargetMin` of one of its highlighted ends places it there. Released anywhere else, it goes back to the hand and nothing is sent.
- **Several doubles (R-31).** After a scoring double the turn stays open and `legal_moves` lists only the doubles that would score. Those stay selectable, and an end turn button shows while `turn_placements` is above 0.
- **Draw and pass.** With no legal move on the local player's turn, a draw button shows in 1v1 while the boneyard holds more than one tile (R-22, R-23); otherwise a pass button shows (R-21). The server still decides; a rejected intent comes back with a fresh view.
- **One intent at a time.** After an intent is sent the hand takes no more input until the next `MatchView` arrives, so a double tap never sends twice.
- Legal tiles and ends show their highlight as soon as the view arrives (section 6 rule 5); the end highlight fades in over `moderate`.

### Board

The chain is laid out from the board the server sends (`BoardView`: the line, the spinner, its top and bottom arms) and fitted to the board area. The layout decides only where tiles are drawn; which ends are open and what they count is the server's.

- Length unit: the short side of a tile. A tile is 2 by 1; a double is 1 along its arm and 2 across it (R-19). The spinner lies across the line.
- The anchor sits at the center: the spinner when there is one (R-17), otherwise the opening tile. Line tiles right of the anchor grow east, those left of it grow west, the top arm north and the bottom arm south (R-18). Each tile shows its touching half nearest the tile it is attached to.
- Folding: every arm runs straight inside a fold box with the board area's aspect. When an arm's next tile that is not a double would cross the box, that tile turns the arm right (east to south, south to west, west to north, north to east). The turning tile lies along the new heading, beside the end it touches. A double never turns an arm.
- Fit: the layout tries fold boxes from one no arm reaches down to a half width of 1, in steps of 1, and drops any where two tiles overlap. The scale of a layout is the largest that fits its bounds in the board area, capped by the largest tile size. It keeps the layout with the highest scale; on a tie, the one with the larger box, so a chain folds only when that makes its tiles larger. The camera centers on the bounds.
- A board of every tile of the set fits on every board shape without overlap (`ChainLayoutTests`).

## 6. Motion

| Duration | ms | Use |
|---|---|---|
| `instant` | 0 | State with no transition |
| `micro` | 80 | Press feedback, tile settle |
| `fast` | 140 | Release, score pop in, small fades |
| `base` | 220 | Tile travel, panel exit, score pop out, scrim |
| `moderate` | 320 | Panel enter, highlight of legal ends |
| `slow` | 480 | Screen transitions, meter fill |
| `emphasis` | 700 | Banner entrances (domino, block, match win) |

| Easing | Control points | Use |
|---|---|---|
| `standard` | 0.2, 0, 0, 1 | Default for moves and counters |
| `enter` | 0, 0, 0.2, 1 | Things arriving |
| `exit` | 0.4, 0, 1, 1 | Things leaving |
| `overshoot` | 0.34, 1.56, 0.64, 1 | Pops, release, tile settle |
| `linear` | 0, 0, 1, 1 | Looping glows, progress |

| Shake | Amplitude | Duration |
|---|---|---|
| `none` | 0 | 0 |
| `small` | 6 | 180 |
| `medium` | 12 | 240 |

Rules:
1. Animate only transform (position, rotation, scale) and opacity or vertex colour. Never animate layout (size, anchors, layout groups), text size, or a material property that creates a material instance; per-renderer values go through a property block.
2. Animated UI sits on its own sub-canvas so a tween does not re-batch static UI.
3. Tweens run from a pre-allocated pool of `maxTweens` per effect level (section 7). Tweens are value types without closures and allocate nothing. When the pool is full, the oldest cosmetic tween jumps to its end state. With no cosmetic tween in the pool, the oldest tween jumps instead, and a pool with no room at all puts the new tween at its end state at once. A new tween on a target and channel (position, rotation, scale, opacity) that is already moving replaces the old one. A tween that ends between frames lands exactly on its end value. Rule 5's jump to the final state finishes every tween at once (`TweenPool`).
4. Input is never blocked by animation. Tile selection and dragging, buttons and emoji work during every effect. An intent is sent on input, never after an animation.
5. Presentation never runs more than `motion.maxPresentationLagMs` (600) behind the latest server state. If queued effects would exceed it, the queue jumps to the final state. Turn ownership, legal-end highlights and the turn timer (R-49) show as soon as the state arrives, never after queued effects. The timer is server time; effects never extend a turn.
6. At most `motion.maxFullScreenFlashesPerSecond` (3) full-screen flashes per second (WCAG 2.2 SC 2.3.1).

### Reduce motion

A settings toggle, defaulting to the OS setting (Android animator duration scale 0, iOS Reduce Motion).

| Motion | Reduce motion on |
|---|---|
| Shake, camera moves | None |
| Scale pops (`overshoot`) | Opacity fade in `fast` with `standard` |
| Tile travel | Kept, `fast`, `standard`, no settle |
| Full-screen flash | None |
| Particles | Counts of the low level, whatever the selected level |
| Any transition longer than `slow` | Capped at `slow`; holds are unchanged |
| Information (scores, banners, timer) | Unchanged; only the motion is reduced |

### Hand motion

Deal, draw and pass are tweens from the pool (rule 3), with no particles and no extra draw calls.

| Motion | Trigger | Presentation | Reduce motion |
|---|---|---|---|
| Deal | A hand is dealt (R-3) | Each tile travels from the table center to its seat in `base` with `enter`; tile n starts n × `micro` after the first | `fast` with `standard`, same spacing |
| Draw | A tile is drawn in 1v1 (R-22) | The tile travels from the boneyard to the hand in `base` with `enter` | `fast` with `standard` |
| Pass | A seat passes (R-21, R-23) | A localised "pass" label at the seat panel pops in (`fast`, `overshoot`), holds `slow`, and leaves (`base`, `exit`); 840 ms in total | Opacity fade in `fast` with `standard` instead of the pop; the hold and the exit are unchanged |

### Haptics

Haptics use the platform's own feedback patterns, so the game sets no duration or strength and the player's system haptics setting applies on top of the game's. A settings toggle turns them off (on by default); it is a device setting (`docs/anti-cheat.md`, Device storage). Haptics follow server views, never input, and at most one cue plays per view: the strongest of win, score and tile place.

| Cue | When | Android `HapticFeedbackConstants` | iOS |
|---|---|---|---|
| Tile place | The board has more tiles than in the previous view and the turn was the local player's | `VIRTUAL_KEY` | `UIImpactFeedbackGenerator`, light |
| Score | The local team's score rose (board points, hand points or carry-over) | `CONFIRM` on Android 11 and later, `VIRTUAL_KEY` before | `UIImpactFeedbackGenerator`, medium |
| Win | The match finished with the local team as winner | `LONG_PRESS` | `UINotificationFeedbackGenerator`, success |

- The first view of a connection plays nothing, so a reconnect does not replay a cue, and a viewer without a seat feels nothing.
- Other players' placements and the other team's points play nothing.

## 7. Effect levels

The effect level follows the graphics level (`docs/performance.md` 1.1): Low uses low, Medium uses medium, High and Ultra use high. The default level per device tier (`docs/performance.md` section 1) is admin config, with the defaults below. The player may choose a lower level, not a higher one. Reduce motion is independent of the level.

| | low | medium | high |
|---|---|---|---|
| Default for tier | Low | Mid | High |
| Target fps | 30 | 60 | 120 |
| Work time p95 gate (`docs/performance.md`) | 28.0 | 14.0 | 7.0 |
| Base scene CPU / GPU ms | 20.0 / 20.0 | 10.0 / 10.0 | 5.0 / 4.5 |
| All effects together, CPU / GPU ms | 4.0 / 6.0 | 3.0 / 4.0 | 1.5 / 2.5 |
| Base scene batches + effect draw calls (gate under 150) | 105 + 20 | 105 + 35 | 105 + 40 |
| Live particles, all effects | 150 | 400 | 800 |
| Overdraw layers, any effect | 2 | 3 | 4 |
| `maxTweens` | 32 | 64 | 96 |
| Animated cosmetics (avatars, emoji) | Static fallback (ADR 0002) | Animated | Animated |
| `maxAnimatedCosmetics` per screen (ADR 0012) | 0 | 10 | 10 |
| Characters (ADR 0009) | Static fallback (ADR 0002) | 3D, `modelAddress` | 3D, `modelHqAddress` where the item has one |

Base scene plus effects stays within the p95 work-time gate; the checker enforces it. The high level is budgeted at 120 fps, so it also holds at 60.

### Concurrency

Effects that can be live in the same frame form a set; each set's sum stays within the level's effect budget. Sums as CPU ms / GPU ms / draw calls / particles:

| Set | Effects | low | medium | high |
|---|---|---|---|---|
| `turn` | tilePlace, scorePopup, scoreCascade, spinnerFormation, emoji | 2.05 / 3.25 / 11 / 44 | 1.9 / 2.9 / 20 / 164 | 1.0 / 1.6 / 22 / 336 |
| `dominoEnd` | tilePlace, scorePopup, scoreCascade, domino, emoji | 2.5 / 3.95 / 12 / 74 | 2.3 / 3.4 / 23 / 254 | 1.25 / 1.9 / 25 / 516 |
| `blockEnd` | tilePlace, scorePopup, scoreCascade, block, emoji | 2.15 / 3.35 / 11 / 46 | 2.0 / 3.0 / 21 / 174 | 1.1 / 1.7 / 23 / 356 |
| `matchEnd` | scorePopup, scoreCascade, matchWin, emoji | 2.85 / 4.7 / 13 / 90 | 2.6 / 3.9 / 25 / 322 | 1.35 / 2.25 / 28 / 652 |
| `results` | scorePopup, rankUp | 1.65 / 2.7 / 6 / 50 | 1.4 / 2.1 / 12 / 160 | 0.7 / 1.25 / 14 / 328 |

Sequencing that keeps the sets true:
- `domino` and `block` start after the last tile's `tilePlace` settles; hand points (section 8) follow the banner.
- `matchWin` starts after the hand-end presentation finishes; it never overlaps `domino` or `block`.
- If the placement that forms the spinner also ends the hand, `spinnerFormation` is skipped.
- `rankUp` plays only on the results screen.

### Measurement

An effect is within budget when the replay harness (`docs/performance.md` section 2, #192) shows it in its worst set on the level's reference device:

| Budget | Method |
|---|---|
| CPU ms | A `ProfilerMarker` around the effect's update, read per frame with `ProfilerRecorder`; worst frame |
| GPU ms | Worst frame captured with the effect on and off (Android GPU Inspector, Xcode Metal System Trace); difference |
| Particles | Sum of live particle counts per frame; maximum |
| Draw calls | Batches with the effect on minus off, in the worst frame (`docs/performance.md` draw call row) |
| Overdraw layers | Overdraw view of the worst frame over the effect's area |
| Pooled | Pool sizes at scene load; `Instantiate` calls during the match stay 0 |

A PR that adds or changes an effect reports these numbers as `docs/performance.md` section 8 requires.

### Emoji wheel

In-match emoji (#151) and the `emoji` effect:

- **Wheel.** An emoji button on the match HUD opens the wheel as a panel (section 5, panel motion). Its slots are the emoji equipped in the player's loadout, in loadout order, up to `EmojiSlots` (#150). With no emoji equipped the button is hidden. Each slot shows the emoji's static art and is at least `touchTargetMin`.
- **Send.** A tap on a slot sends `EmojiIntent` at once (section 6 rule 4) and closes the wheel. The client shows nothing on its own: the emoji appears for every seat, the sender included, when `EmojiShown` arrives (`proto/README.md`). The server enforces ownership and the spam limit.
- **Calm down.** After a send the button and the slots show `opacity.disabled` until the sender's own emoji has finished its `durationMs` (1800). If no `EmojiShown` comes back, because the server dropped the emoji, they are enabled again 1800 ms after the send. Opening and closing the wheel stay possible.
- **Pop.** The emoji pops at the sender's avatar: scale 0 to 1 in `base` with `overshoot`, a hold, then opacity 1 to 0 in `base` with `exit`, `durationMs` in total. With reduce motion the scale pop becomes an opacity fade in `fast` with `standard` (Reduce motion table). Each seat shows one live emoji; a new one replaces it from the start.
- **Art.** On the low effect level the emoji shows its static art (`staticAddress`). On medium and high it plays its one looping animation (`animationAddress`) at the frame rate stored with that animation, and falls back to the static art until the animation is loaded (ADR 0002).
- **Pooling.** The `pooled` count of the `emoji` budget (4) is prewarmed when the match scene loads, so no instance is created during the match. A match has at most four seats with one live emoji each, so the pool never runs out.

## 8. Score cascade

Board points are multiples of 5 (R-25); a score event's step comes from its value:

| Step | Points | Text scale | `score` size | Particles low / medium / high | Glow | Shake | Hold ms |
|---|---|---|---|---|---|---|---|
| 1 | 5 | 1.0 | 108 | 5 / 14 / 27 | soft | none | 500 |
| 2 | 10 | 1.15 | 124 | 9 / 27 / 54 | soft | none | 550 |
| 3 | 15 | 1.3 | 140 | 14 / 41 / 81 | strong | none | 600 |
| 4 | 20 | 1.45 | 157 | 18 / 54 / 108 | strong | small | 650 |
| 5 | 25 | 1.6 | 173 | 24 / 72 / 144 | intense | small | 700 |
| 6 | 30 and more | 1.8 | 194 | 30 / 90 / 180 | intense | medium | 800 |

Particles are `scoreCascade` particles of the level times the step's `particleShare`, rounded. The popup pops in with `fast` and `overshoot`, holds, and pops out with `base` and `exit`; the longest popup is 140 + 800 + 220 = 1160 ms, the `scorePopup` lifetime.

| Event | Presentation |
|---|---|
| Board points (R-25), including the 5-5 opening (R-29, 10 points) | One popup at the placed tile, step from the value |
| Several doubles in one turn (R-31) | Each scoring placement gets its own popup, `scoreCascade.chainStepGapMs` (120) apart. The step is raised by `chainBoost`: placement 2 adds 1 step, placement 3 and later add 2, capped at step 6. After the last placement of a chain of two or more, a turn-total popup shows the sum, step from the sum without boost. Presentation only: each placement's points are exactly the server's value |
| Hand points from a domino (R-33) or a block (R-37) | Popup with the step from the value, then the team meter counts up over `rollMsPer5Points` (40) per 5 points, at most `rollMaxMs` (1200), with `standard` |
| Carry-over (R-39) | A second popup `carryOverGapMs` (200) after the hand points, step from the carry-over value, then the meter roll continues |
| Hand points not awarded (R-41) | No popup and no cascade; the team meter shows its lock badge |

The team meter marks `HandPointsLockThreshold` (R-41) and `TargetScore` (R-43). Both values come from the server's rules config, never from tokens.

Worked from `docs/rules.md`:

| Rules example | Events | Steps |
|---|---|---|
| 1, step 3 | West scores 10 | 2 |
| 2 | 5-5 opening scores 10 | 2 |
| 3 | 0-0 scores 5, then 5-5 scores 10 in the same turn; turn total 15 | 1, 2 + 1 = 3; total 3 |
| 6 | A scores 25 from a block | 5; roll 200 ms |
| 7 | B scores 15 hand points and 35 carry-over | 3, then 6; roll of 50 points 400 ms |
| 8 | B scores 80 from a block | 6; roll 640 ms (the 1200 ms cap starts at 150 points) |

The step table, chain boost and roll timings are admin config with these defaults, so they can be tuned without a release. Until that config reaches the client, `UI/Motion/ScoreCascade` reads the defaults from `TokenScoreCascade`. Particle counts round half up, and a step's text size is the `score` size times its text scale, rounded. With reduce motion a popup fades in and out instead of scaling, the shake is dropped and particles use the low level's counts.

### Score panel and hand summary

The panel and the summary only present values from the latest `MatchView` (`proto/README.md`); the client computes no score. `Game/Match/ScoreBoard` and `Game/Match/HandSummary` hold them.

- **Team meters.** One meter per team, the local player's team first (team A for a viewer without a seat), filled to the team score over `target_score`, never past full, with a mark at `hand_points_lock_threshold`. A team in `locked_teams` shows the lock badge for the whole hand (R-41).
- **Hand summary.** When a new `last_result` arrives it shows how the hand ended (`ending`), the tiles each seat had left (`left`), each team's pips, and how the award was made: the counted pips of the other team, the hand points they rounded up to (`awarded` minus `carried_in`), and the carry-over added (`carried_in`, R-39). A locked winner (`hand_points_locked`) shows the lock instead of hand points. A block with equal totals (no winner) shows the pips kept as `carry_over` for the next hand (R-38).
- `left` comes only in the first view of a connection after a hand ends, so the summary opens on a view that carries `left` for a hand it has not shown yet, keeps those tiles until the next hand end, and stays closed after a reconnect during play.

## 9. Open items

- Screen orientation is not decided; units follow the short side so the tokens hold either way.
- Sound per step is not part of this spec.
- The largest tile size on the board (the board layout's scale cap) and the board area are not decided; they belong to the match screen layout.
