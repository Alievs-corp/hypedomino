# UI, motion and effects design system

Status: proposal. This document and `docs/design-tokens.json` are where colour, typography, shape, duration, easing and effect-budget values are born. Every value is an initial proposal; the owner approves values by merging the pull request that adds or changes them. A later change edits the JSON and the generated tables in the same PR.

`docs/design-tokens.json` is the single source of the values. This file explains how they are used. `node tools/design-tokens/design-tokens.mjs` checks the tokens (contrast, frame-budget sums, monotonic score steps) and that the contrast table below matches them; CI runs it through `npm run test:tools`.

Frame, draw call, GC and tier definitions come from `docs/performance.md` and are not changed here. Client engine and asset delivery: `docs/adr/0001-client-unity.md`, `docs/adr/0002-asset-delivery.md`. Score events come from `docs/rules.md`; the client never computes a score, it presents the values the server sends.

## 1. Units

| Quantity | Unit |
|---|---|
| Length (type, radius, spacing, shake) | UI units on a canvas scaled to a 1080-unit short side (Canvas Scaler, scale with screen size, match the short side). Independent of orientation |
| Duration | ms |
| Easing | cubic-bezier `x1, y1, x2, y2` |
| Effect cost | ms of frame work time (`docs/performance.md` section 2) on the reference device of the level's tier |

On a 6.5-inch 20:9 phone the short side is about 2.67 in, so 1 in is about 405 units and 48 dp is about 120 units.

## 2. Colour

The game is drawn on dark, layered backgrounds so vivid fills, glows and particles read at full saturation. Vivid fills carry dark ink text (`on`); white on these fills is only 1.31:1 to 3.31:1, under AA. Coloured text on a dark layer uses the role's `text` shade, never its `fill`.

|---|---|---|
| `color.background.base` | `#0D0B24` | Screen background, lowest layer |
| `color.background.raised` | `#17143A` | Bars, trays, the hand area |
| `color.surface.default` | `#221D52` | Panels, cards |
| `color.surface.raised` | `#2D2768` | Panel inside panel, list rows, inputs |
| `color.scrim` | `#06051A` | Behind modals, at `opacity.scrim` |

| Token | Value | Use |
|---|---|---|
| `opacity.disabled` | 0.4 | Disabled controls |
| `opacity.scrim` | 0.72 | Modal scrim |
| `opacity.pressedTint` | 0.85 | Vertex-colour multiplier on a pressed fill |

Rules:
- Colour is never the only cue. Team identity also shows as seat position and the team badge; `success`, `warning` and `danger` always come with an icon. Team A blue and team B orange stay distinct under protan and deutan simulation (Viénot 1999); `primary` and `danger` are close under it, which is why danger carries an icon.
- Rarity colours are not defined here. `rarity` in the tokens is only a reference to #5, which owns those values.
- UI, effect, team, score and role colours come only from these tokens. Cosmetic illustration art (avatars, characters, tables, frames, emoji) uses its own palette per asset, reviewed on the reference board (`docs/art-direction.md` section 9); it is never dominated by a team or role hue and never evokes a flag or political side (`docs/localization.md` 6).

## 3. Typography

| Family | Licence | Weights | Use |
|---|---|---|---|
| Unbounded (display) | SIL OFL 1.1 | 700, 900 | Titles, banners, score popups |
| Nunito (ui) | SIL OFL 1.1 | 600, 800, 900 | Body, labels, buttons, any number that changes while visible |

Launch languages are AZ, EN, TR and RU. Coverage was verified on the variable font files `ofl/unbounded/Unbounded[wght].ttf` and `ofl/nunito/Nunito[wght].ttf` from the `google/fonts` repository at commit `e7db6ca`, by reading each file's `cmap` table with fontTools 4.63 and checking every code point below. Both families cover all of them.

| Set | Code points | Unbounded | Nunito |
|---|---|---|---|
| Basic Latin | U+0020 to U+007E | 95/95 | 95/95 |
| Azerbaijani and Turkish letters | ƏəĞğIıİiŞşÇçÖöÜü | 16/16 | 16/16 |
| Turkish circumflex | ÂâÎîÛû | 6/6 | 6/6 |
| Russian Cyrillic | U+0410 to U+044F, Ё, ё | 66/66 | 66/66 |
| Currency | ₼ ₺ ₽ € $ | 5/5 | 5/5 |
| Punctuation | « » — – … № ’ “ ” • · × | 12/12 | 12/12 |

Rubik was checked the same way and rejected: it has no Ə, ə, ₼ or ₺. Nunito's ten digits share one advance width (600 units), so counters do not jitter; Unbounded's digits have nine different widths, so it is used only for numbers that do not change while visible.

| Style | Family | Weight | Size | Line height |
|---|---|---|---|---|
| `caption` | ui | 600 | 30 | 1.3 |
| `body` | ui | 600 | 38 | 1.35 |
| `label` | ui | 800 | 44 | 1.2 |
| `counter` | ui | 900 | 56 | 1.0 |
| `title` | display | 700 | 54 | 1.15 |
| `heading` | display | 900 | 68 | 1.1 |
| `display` | display | 900 | 86 | 1.05 |
| `score` | display | 900 | 108 | 1.0 |

Rules:
- No text under 30 units (`typography.minimumSize`).
- Each family ships as a static SDF atlas holding the sets above plus every glyph in the localisation tables. No dynamic atlas in the match scene: adding a glyph at runtime allocates and stalls a frame.
- At most three material presets per family (plain, outline, glow); each preset costs a draw call.
- No runtime case conversion. Turkish and Azerbaijani map i to İ and ı to I, which culture-invariant upper-casing breaks; strings arrive from localisation already in their final case.
- Text size never animates. A text pop scales its transform.

## 4. Shape, space, elevation and glow

| Group | Tokens |
|---|---|
| `radius` | sm 8, md 16, lg 24, xl 36, pill 999 |
| `spacing` | xxs 4, xs 8, sm 12, md 16, lg 24, xl 32, xxl 48, xxxl 64 |
| `size.touchTargetMin` | 120 (about 48 dp) |
| `elevation` | e0 none; e1 offset 4, alpha 0.35; e2 offset 8, alpha 0.45; e3 offset 16, alpha 0.55 |
| `glow` | none; soft alpha 0.35, scale 1.15; strong alpha 0.55, scale 1.3; intense alpha 0.8, scale 1.5 |

- Shadows are a baked 9-slice sprite in `color.shadow`, offset down by the elevation's offset. No runtime blur.
- Glow is an additive sprite from the same atlas, tinted with a role `fill`, scaled from its owner by the glow's scale. It counts as one overdraw layer.
- No full-screen post-processing (bloom, blur, colour grading passes) in the match scene at any effect level.

## 5. Buttons and panels

| Element | Rest | Pressed | Released | Disabled |
|---|---|---|---|---|
| Button | Role `fill`, label in `label` style and role `on`, radius md (primary: pill), elevation e1, height at least `touchTargetMin`. Only the screen's primary button has `glow.soft` | Scale to `motion.pressScale` 0.94 in `micro` with `standard`; vertex tint `opacity.pressedTint` | Scale back to 1 in `fast` with `overshoot`. The action fires on pointer up inside, at once, not after the animation | `opacity.disabled`, no glow, no press motion |
| Panel | `surface.default`, radius lg, elevation e2, padding lg | - | - | - |

| Panel motion | Animation |
|---|---|
| Enter | Scale `motion.panelEnterScale` 0.92 to 1 and opacity 0 to 1, `moderate`, `enter` |
| Exit | Opacity 1 to 0 and scale 1 to 0.92, `base`, `exit` |
| Modal | Scrim fades to `opacity.scrim` in `base` alongside the panel |

- One primary button per screen. Destructive actions use `danger` and an icon.
- Close and back work during enter and exit animations; an exit interrupted by a new enter reverses from its current value.
- Clipping uses rectangle masks only; stencil masks break batching.

## 6. Motion

| Duration | ms | Use |
|---|---|---|
| `instant` | 0 | State with no transition |
| `micro` | 80 | Press feedback, tile settle |
| `fast` | 140 | Release, score pop in, small fades |
| `base` | 220 | Tile travel, panel exit, score pop out, scrim |
| `moderate` | 320 | Panel enter, highlight of legal ends |
| `slow` | 480 | Screen transitions, meter fill |
| `emphasis` | 700 | Banner entrances (domino, block, match win) |

| Easing | Control points | Use |
|---|---|---|
| `standard` | 0.2, 0, 0, 1 | Default for moves and counters |
| `enter` | 0, 0, 0.2, 1 | Things arriving |
| `exit` | 0.4, 0, 1, 1 | Things leaving |
| `overshoot` | 0.34, 1.56, 0.64, 1 | Pops, release, tile settle |
| `linear` | 0, 0, 1, 1 | Looping glows, progress |

| Shake | Amplitude | Duration |
|---|---|---|
| `none` | 0 | 0 |
| `small` | 6 | 180 |
| `medium` | 12 | 240 |

Rules:
1. Animate only transform (position, rotation, scale) and opacity or vertex colour. Never animate layout (size, anchors, layout groups), text size, or a material property that creates a material instance; per-renderer values go through a property block.
2. Animated UI sits on its own sub-canvas so a tween does not re-batch static UI.
3. Tweens run from a pre-allocated pool of `maxTweens` per effect level (section 7). Tweens are value types without closures and allocate nothing. When the pool is full, the oldest cosmetic tween jumps to its end state.
4. Input is never blocked by animation. Tile selection and dragging, buttons and emoji work during every effect. An intent is sent on input, never after an animation.
5. Presentation never runs more than `motion.maxPresentationLagMs` (600) behind the latest server state. If queued effects would exceed it, the queue jumps to the final state. Turn ownership, legal-end highlights and the turn timer (R-49) show as soon as the state arrives, never after queued effects. The timer is server time; effects never extend a turn.
6. At most `motion.maxFullScreenFlashesPerSecond` (3) full-screen flashes per second (WCAG 2.2 SC 2.3.1).

### Reduce motion

A settings toggle, defaulting to the OS setting (Android animator duration scale 0, iOS Reduce Motion).

| Motion | Reduce motion on |
|---|---|
| Shake, camera moves | None |
| Scale pops (`overshoot`) | Opacity fade in `fast` with `standard` |
| Tile travel | Kept, `fast`, `standard`, no settle |
| Full-screen flash | None |
| Particles | Counts of the low level, whatever the selected level |
| Any transition longer than `slow` | Capped at `slow`; holds are unchanged |
| Information (scores, banners, timer) | Unchanged; only the motion is reduced |

## 7. Effect levels

The effect level follows the graphics quality setting. The default level per device tier (`docs/performance.md` section 1) is admin config, with the defaults below. The player may choose a lower level, not a higher one. Reduce motion is independent of the level.

| | low | medium | high |
|---|---|---|---|
| Default for tier | Low | Mid | High |
| Target fps | 30 | 60 | 120 |
| Work time p95 gate (`docs/performance.md`) | 28.0 | 14.0 | 7.0 |
| Base scene CPU / GPU ms | 20.0 / 20.0 | 10.0 / 10.0 | 5.0 / 4.5 |
| All effects together, CPU / GPU ms | 4.0 / 6.0 | 3.0 / 4.0 | 1.5 / 2.5 |
| Base scene batches + effect draw calls (gate under 150) | 105 + 20 | 105 + 35 | 105 + 40 |
| Live particles, all effects | 150 | 400 | 800 |
| Overdraw layers, any effect | 2 | 3 | 4 |
| `maxTweens` | 32 | 64 | 96 |
| Animated cosmetics (avatars, emoji) | Static fallback (ADR 0002) | Animated | Animated |

Base scene plus effects stays within the p95 work-time gate; the checker enforces it. The high level is budgeted at 120 fps, so it also holds at 60.

### Effects

| Effect | Trigger | Presentation |
|---|---|---|
| `tilePlace` | Any placement (R-15) | Tile travels to its end (`base`, `standard`), settles (`micro`, `overshoot`), dust burst |
| `scorePopup` | Any score event (section 8) | "+N" in `score` style and `role.score.text`, scaled by the score step, pops in, holds, pops out |
| `scoreCascade` | Same, scaled by step | Particle burst and glow at the popup; points fly to the team meter |
| `spinnerFormation` | A double becomes the spinner (R-17, R-18) | Ring pulse on the double, arm markers slide out on the two new ends |
| `domino` | Hand ends in a domino (R-32) | Localised banner in the winning team colour, burst from the last tile |
| `block` | Hand ends in a block (R-36) | Lock stamp across the board, board dims with the scrim colour at low alpha |
| `matchWin` | Match ends (R-46) | Banner, confetti in the winning team colour |
| `rankUp` | Results screen, rank rises | Rank badge scales in, rays |
| `emoji` | A player sends an emoji | Emoji pops at the sender's avatar; one live emoji per seat, a new one replaces it |

### Concurrency

Effects that can be live in the same frame form a set; each set's sum stays within the level's effect budget. Sums as CPU ms / GPU ms / draw calls / particles:

| Set | Effects | low | medium | high |
|---|---|---|---|---|
| `turn` | tilePlace, scorePopup, scoreCascade, spinnerFormation, emoji | 2.05 / 3.25 / 11 / 44 | 1.9 / 2.9 / 20 / 164 | 1.0 / 1.6 / 22 / 336 |
| `dominoEnd` | tilePlace, scorePopup, scoreCascade, domino, emoji | 2.5 / 3.95 / 12 / 74 | 2.3 / 3.4 / 23 / 254 | 1.25 / 1.9 / 25 / 516 |
| `blockEnd` | tilePlace, scorePopup, scoreCascade, block, emoji | 2.15 / 3.35 / 11 / 46 | 2.0 / 3.0 / 21 / 174 | 1.1 / 1.7 / 23 / 356 |
| `matchEnd` | scorePopup, scoreCascade, matchWin, emoji | 2.85 / 4.7 / 13 / 90 | 2.6 / 3.9 / 25 / 322 | 1.35 / 2.25 / 28 / 652 |
| `results` | scorePopup, rankUp | 1.65 / 2.7 / 6 / 50 | 1.4 / 2.1 / 12 / 160 | 0.7 / 1.25 / 14 / 328 |

Sequencing that keeps the sets true:
- `domino` and `block` start after the last tile's `tilePlace` settles; hand points (section 8) follow the banner.
- `matchWin` starts after the hand-end presentation finishes; it never overlaps `domino` or `block`.
- If the placement that forms the spinner also ends the hand, `spinnerFormation` is skipped.
- `rankUp` plays only on the results screen.

### Measurement

An effect is within budget when the replay harness (`docs/performance.md` section 2, #192) shows it in its worst set on the level's reference device:

| Budget | Method |
|---|---|
| CPU ms | A `ProfilerMarker` around the effect's update, read per frame with `ProfilerRecorder`; worst frame |
| GPU ms | Worst frame captured with the effect on and off (Android GPU Inspector, Xcode Metal System Trace); difference |
| Particles | Sum of live particle counts per frame; maximum |
| Draw calls | Batches with the effect on minus off, in the worst frame (`docs/performance.md` draw call row) |
| Overdraw layers | Overdraw view of the worst frame over the effect's area |
| Pooled | Pool sizes at scene load; `Instantiate` calls during the match stay 0 |

A PR that adds or changes an effect reports these numbers as `docs/performance.md` section 8 requires.

## 8. Score cascade

Board points are multiples of 5 (R-25); a score event's step comes from its value:

| Step | Points | Text scale | `score` size | Particles low / medium / high | Glow | Shake | Hold ms |
|---|---|---|---|---|---|---|---|
| 1 | 5 | 1.0 | 108 | 5 / 14 / 27 | soft | none | 500 |
| 2 | 10 | 1.15 | 124 | 9 / 27 / 54 | soft | none | 550 |
| 3 | 15 | 1.3 | 140 | 14 / 41 / 81 | strong | none | 600 |
| 4 | 20 | 1.45 | 157 | 18 / 54 / 108 | strong | small | 650 |
| 5 | 25 | 1.6 | 173 | 24 / 72 / 144 | intense | small | 700 |
| 6 | 30 and more | 1.8 | 194 | 30 / 90 / 180 | intense | medium | 800 |

Particles are `scoreCascade` particles of the level times the step's `particleShare`, rounded. The popup pops in with `fast` and `overshoot`, holds, and pops out with `base` and `exit`; the longest popup is 140 + 800 + 220 = 1160 ms, the `scorePopup` lifetime.

| Event | Presentation |
|---|---|
| Board points (R-25), including the 5-5 opening (R-29, 10 points) | One popup at the placed tile, step from the value |
| Several doubles in one turn (R-31) | Each scoring placement gets its own popup, `scoreCascade.chainStepGapMs` (120) apart. The step is raised by `chainBoost`: placement 2 adds 1 step, placement 3 and later add 2, capped at step 6. After the last placement of a chain of two or more, a turn-total popup shows the sum, step from the sum without boost. Presentation only: each placement's points are exactly the server's value |
| Hand points from a domino (R-33) or a block (R-37) | Popup with the step from the value, then the team meter counts up over `rollMsPer5Points` (40) per 5 points, at most `rollMaxMs` (1200), with `standard` |
| Carry-over (R-39) | A second popup `carryOverGapMs` (200) after the hand points, step from the carry-over value, then the meter roll continues |
| Hand points not awarded (R-41) | No popup and no cascade; the team meter shows its lock badge |

The team meter marks `HandPointsLockThreshold` (R-41) and `TargetScore` (R-43). Both values come from the server's rules config, never from tokens.

Worked from `docs/rules.md`:

| Rules example | Events | Steps |
|---|---|---|
| 1, step 3 | West scores 10 | 2 |
| 2 | 5-5 opening scores 10 | 2 |
| 3 | 0-0 scores 5, then 5-5 scores 10 in the same turn; turn total 15 | 1, 2 + 1 = 3; total 3 |
| 6 | A scores 25 from a block | 5; roll 200 ms |
| 7 | B scores 15 hand points and 35 carry-over | 3, then 6; roll of 50 points 400 ms |
| 8 | B scores 80 from a block | 6; roll 640 ms (the 1200 ms cap starts at 150 points) |

The step table, chain boost and roll timings are admin config with these defaults, so they can be tuned without a release.

## 9. Open items

- Sound and haptics per step are not part of this spec.
- Rarity colours and their glow levels: #5.
